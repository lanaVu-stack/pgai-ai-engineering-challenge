# Architecture

The project uses a small Python application as the entry point for initiating outbound test calls. Configuration values are loaded from environment variables using `python-dotenv`, including the Retell API key, the Retell phone number, and the Pretty Good AI assessment number. The Python script initializes the Retell SDK and creates an outbound phone call. Retell provides the telephony and conversational voice-agent layer, while the simulated patient follows scenario-specific instructions and interacts with Pretty Good AI's healthcare receptionist. Retell also provides the call recordings and transcripts that are reviewed after each test.

I chose Retell instead of building the realtime voice and telephony pipeline directly with a lower-level provider such as Twilio. A lower-level approach would provide more control over audio streaming and call behavior, but it would also require more time to implement speech generation, realtime audio handling, interruption logic, and turn-taking. Because this challenge prioritizes coherent voice interaction, realistic patient behavior, bug discovery, and iteration, a managed voice-agent platform was the better fit for the time available. During early calls, the patient responded too quickly during the automated opening message, so I adjusted response eagerness, interruption sensitivity, welcome-message behavior, and the patient prompt. Later calls showed cleaner turn-taking and more natural conversational pacing.
